RocketShip PMs need this handled: Ingest the the signals from Slack, tickets, and docs into a clear synthesis the team can act on. ## 01 Context · Data Requirements

**Required sources, and exclusions**

RocketShip Product Strategy One-Pager: Defines the priority framework (P0–P3) Juno will use to reason about every signal it encounters. 
Engineering Capacity Note: Establishes hard constraints. Understand what engineering cannot take on, not just what's planned.
Product Quarterly Roadmap: The committed vs. uncommitted split.
Raw Signals: Raw input Juno is presumably processing. The signals to do anything useful.
Sales Pipeline Snapshot: Surfaces business risk (Pearson at-risk renewal, Acme hard blocker). Influence how Juno weights urgency.

## 04 Memory · Data Requirements

**What persists, at what scope**

Tier 1: Session memory
The current conversation thread
Intermediate reasoning steps
Draft outputs not yet confirmed by a human
Tool call results from this session

Tier 2: Working memory (persist within a quarter)
Item	Written by	Expires
Processed signal log	Juno (autonomously)	End of quarter
Conflict flags raised	Juno (autonomously)	Resolved or end of quarter
Escalations fired	Juno (autonomously)	Acknowledged by human
Capacity snapshot	Human-confirmed	Refreshed when Engineering updates it
Roadmap state	Human-confirmed	Refreshed when Product updates it

Tier 3: Long-term memory
Confirmed priority decisions with rationale ("we deprioritised dark mode because X")
Patterns identified across multiple quarters ("export reliability signals recur every quarter")
Resolved conflicts and how they were resolved
Institutional context a human explicitly told Juno to remember

**Expiry and write rules**

A human mediator’s override is written as the final state and never expires. The model’s original determination is retained alongside it for audit, clearly marked superseded. Model output never overwrites a human decision.

## 06 Verification · AI Testing & Measurement

**The check before output ships**

Every determination must cite at least one real item that appears verbatim in the document pulled this session. Paraphrased or reconstructed clauses fail the check.

**Failure behaviour**

If it cannot find a clear rule to support a ticket, it stops and says “I do not have enough evidence to decide” and routes to a human. It never produces a better-sounding citation to pass the gate. Cautious beats guessing, and an unverified determination is surfaced labelled, never quietly dropped.
